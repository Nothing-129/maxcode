# 智能体自动更新

所有已开启、已安装的内置和自定义智能体均自动更新，不提供独立开关。
关闭智能体总开关后不自动检测或切换新版。旧的 `MAXCODE_AGENT_AUTO_UPDATE`
配置不再读取。

Electron 的 Rust 服务、独立服务器及旧 Tauri 后端在启动 30 秒后开始检查，
此后每 6 小时检查一次。失败后等待 30 分钟重试。关闭设置页不停止后台任务；
退出 MaxCode / 停止服务器后不再执行。在线版本检测同样采用 6 小时周期，
只自动检查开启的智能体，手动“检查更新”仍立即执行。

## 更新来源与安装

- **npm**：从 `https://npm.aifalao.net` 查询、安装具体版本，包括普通包、
  scoped 包及自定义智能体。使用独立 npm prefix，保留平台可选依赖。
- **二进制**：从 ACP 发布目录取得当前平台的真实下载地址和发布的 SHA-256，
  校验后解包到独立目录。保留需要完整运行目录的智能体及其必需附属文件。
  不通过替换旧 URL 的版本字符串猜测新版下载地址。
- **uvx / Python**：从 PyPI 查询包版本，使用独立 `UV_TOOL_DIR` 和
  `UV_TOOL_BIN_DIR` 安装，保留包 extras 和声明的 Python 版本。

手动定义的二进制如果没有可核实的发布源，或包地址 / 版本无法解析，设置页会
显示无法获取更新。不会将其误报为“已是最新版”，也不会安装名称相似的其他产品。
自动更新不执行已禁用智能体或未安装智能体的首次安装。

## 验证与生效

安装目录位于系统本地应用数据目录下的 `app.codeg/agent-updates/<agent>/`，
自定义智能体使用 `custom-<id>`，兼容 Windows 路径。每次安装使用独立 UUID
目录；只有验证通过、对应智能体没有存活或退出中的会话时，才原子替换
`active.json`。下载期间不阻塞新会话，已运行会话继续使用旧文件。

- Codex 额外验证 ACP 适配器依赖的 CLI（`cli --version`）。
- Grok 的安装和验证使用私有 `GROK_HOME`，避免提前改写用户的二进制。
  生效后直接启动对应版本的原生文件，继续使用用户正常的配置目录。
- 自定义版本探测使用声明的参数，但始终执行本次安装的文件，不回退到 PATH。
- npm、Python 安装及二进制下载有限时保护。失败的临时目录清理，旧安装保留。
- 旧的成功安装暂不后台清理。可执行文件和版本验证不等同于完整 ACP 兼容性测试。

智能体详情的「版本状态」分类显示检查、下载验证、等待会话结束、完成、错误
或更新来源不可用，不另设自动更新卡片。切换成功发出
`app://acp-agents-updated`，版本列表跟随后端刷新。

手动安装 / 卸载与自动更新发布互斥。成功手动安装清除自动版本的选择标记，
恢复原有安装解析；手动操作发生后，已准备好的自动候选不会立即覆盖它。
自动更新管理的是 MaxCode 使用的安装，不替换用户另外安装的全局 CLI。

契约：`settings.agent-auto-updates`。前端独立契约：
`src/maxcode-contracts/agent-auto-updates.contract.test.tsx`；后端测试：
`src-tauri/src/commands/agent_auto_updates.rs`。
