## 队列生命周期与错误语义

原生追加的在途条目及锁由原有轻量 tab 队列拥有，不放在易卸载的重型聊天面板中。
请求开始前同步认领条目，期间自动发送无法取走它，重复点击、编辑、删除不能改变该条内容。
成功只删除被确认的条目；明确的 `NoActiveTurn` 保留原条目供正常队列发送。
网络等其他失败不能证明后端没有接收，因此保留并标记 `flushBlocked`，等待用户主动处理，
避免自动发送第二遍。完成回调始终释放在途锁。

队列追加始终发送原始完整 blocks（即使仅有文字），复用后端“pull 不接受 blocks”的
已有约束；能力在 UI 读取与发送之间降级时，会拒绝并保留消息，不能悄悄变成待读备注。
新独立 Rust 契约专门覆盖纯文字 blocks 的这一边界。
